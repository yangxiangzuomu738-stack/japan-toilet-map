# デザイン依頼書 その8：「どこにあるトイレか」を示す

## 背景

利用者から要望がありました。

> スーパーマーケットなどの商業施設や駅・駅ビルの中にあるトイレも表示、検索できるようにしてください。

調べたところ、**駅や商業施設の中のトイレは、実はすでに地図に出ています**。
問題は次の2点です。

1. **どこにあるトイレなのか分からない。**
   駅の中のトイレも、OpenStreetMap には名前が付いていないことがほとんどで、
   詳細を開いても「名前の情報はありません」としか出ません。
   利用者から見ると「これは駅の中なのか、路上なのか」が分かりません。
2. **施設名で検索できない。**
   「新宿駅」と入力しても、新宿駅の中のトイレは見つかりません。
   検索が対象にしているのはトイレ自体の名前だけで、それは全体の 4% ほどしかないからです。

そこで、**各トイレに「場所」（どの施設の中／そばにあるか）を結び付けます**。
これはデータ側（Claude Code 担当）で処理します。
あなたには、その「場所」を **どう見せるか** を設計してほしいです。

## 新しくデータに入る情報

各トイレに、次の情報が加わります（分からないものは空・0）。

| キー | 意味 | 値 |
|---|---|---|
| `place` | 場所の名前 | 例「新宿駅」「イオンモール幕張新都心」「日比谷公園」／不明なら空 |
| `placeKind` | 場所の種類 | 0=なし 1=駅・駅ビル 2=商業施設 3=公園 4=道の駅・SA/PA 5=公共施設 |
| `inside` | 位置関係 | `true`=その施設の敷地・建物の**中**／`false`=**そば**（近くにある） |
| `placeDistance` | そばの場合の距離 | 例 35（メートル）。中にある場合は使いません |
| `derived` | 記録の種類 | `false`=トイレそのものが地図に記録されている（位置は正確）／`true`=**施設に「トイレあり」と記録されているだけ**（位置はその施設の代表点で、建物内のどこにあるかは不明） |

### `derived` がとても重要です

`derived: true` のものは、**「この施設にはトイレがある」という記録があるだけ**で、
トイレそのものの位置は記録されていません。
地図上の点は施設の代表点なので、実際のトイレはその建物のどこかにあります。

**これを普通のトイレと同じ見た目にしてはいけません。**
利用者が「ここに行けばトイレがある」と思って建物の外の一点に向かってしまうためです。
「この施設のどこかにトイレがあります」と伝わる見せ方にしてください。

## 作ってほしいもの

対象: `web/design/ui-place.html`（新規）、`web/styles.css`（追記）、
`web/design/icons.js`（追記）、`web/design/DESIGN_SPEC.md`（追記）

`web/index.html` と `web/js/*.js` は Claude Code 担当です。読むだけで編集しないでください。

### 1. 地図のマーカー：`derived` 用の見た目

`icons.js` の `TMIcons.marker(kind, selected)` は現在、
`kind` に `'yes' | 'no' | 'unknown'`（車いす対応の有無）を取り、
ピン／盾／ひし形の3種類のSVGを返しています。

これに加えて、**施設に「トイレあり」とだけ記録されているもの用のマーカー**を、
`TMIcons.facilityMarker(kind, selected)` という別の関数として作ってください。

- 同じ 32×40 の viewBox、同じ `currentColor` の使い方にすること
  （Claude Code が色を差し替えてラスタライズします）
- 車いす対応の有無（`kind`）は、これまでと同じく **形でも** 区別すること
- そのうえで、**「正確な位置ではない／施設のどこか」**が直感的に伝わる形にすること
  （輪郭を破線にする、下端を尖らせない、など。判断はお任せします）
- 選択中の状態も用意すること

### 2. 凡例への追加

`#map-legend` の中に、この新しいマーカーの説明を1行足す前提で、
**HTML断片とCSS**を用意してください。

- 文言案（より分かりやすい案があれば変えてかまいません）:
  「この施設のどこかにトイレあり（正確な場所は不明）」
- 既存の `.legend-item` / `.legend-marker` の書き方に合わせること
- 凡例が今より縦に伸びるので、**スマホで地図を隠しすぎないか**を確認して調整してください

### 3. 詳細パネルへの「場所」の追加

`#detail-panel` の属性一覧（`.attribute-list`）の**いちばん上**に、
「場所」の行を足す前提でHTML断片を用意してください。

- `id="attribute-place-icon"`（アイコン）、`id="attribute-place-value"`（値）
- アイコンは `icons.js` に **`place`** を追加してください（建物と目印が分かるもの）
- 値に入る文字列の例:
  - 「新宿駅 の中」
  - 「イオンモール幕張新都心 の中」
  - 「日比谷公園 のそば（約35m）」
  - 「不明」
- 施設名は長くなることがあります（例「日本橋室町三井タワー [COREDO室町テラス]」）。
  **折り返して全部読めるように**してください。既存の属性行は右寄せ1行の想定なので、
  場所の行だけ別の見せ方にしてよいです。

さらに、`derived: true` のときだけ表示する注意書きを作ってください。

- `id="detail-derived-note"`、クラス `.detail-note`（既存の `#detail-unknown-note` と同じ体裁）
- 文面（そのまま使ってください）:
  > この施設に「トイレあり」と記録されていますが、
  > 建物のどこにあるかまでは記録されていません。
  > 地図の印は施設の代表点です。

### 4. 絞り込みへの「場所の種類」追加

`#filter-panel` の `.filter-list` に、場所の種類で絞る項目を足します。
既存の `.filter-option` と同じ体裁で、次の5つのHTML断片を用意してください。

| id | ラベル | 補足 |
|---|---|---|
| `filter-place-station` | 駅・駅ビルの中 | |
| `filter-place-shop` | 商業施設の中 | スーパー・百貨店・ショッピングモールなど |
| `filter-place-park` | 公園の中 | |
| `filter-place-roadside` | 道の駅・サービスエリア | |
| `filter-place-public` | 公共施設の中 | 市役所・図書館・公民館など |

これらは既存の条件（車いす対応あり、など）とは **性質が違う**（＝場所の種類の選択で、
複数選ぶと「どれか」に当てはまるもの、という意味になります）。
既存の条件と混ざって誤解されないよう、**見出しを付けて区切って**ください。

- 場所の種類の見出し: 「場所の種類」（`id="filter-place-heading"`）
- 既存の条件の見出し: 「設備・条件」（`id="filter-feature-heading"`）
- 複数選んだときの意味が分かる一文を添えてください
  （例「選んだ場所のどれかに当てはまるトイレを表示します」）

### 5. 一覧パネルへの「場所」表示

`.list-item` の中身（`web/design/ui-list.html` で設計済み）に、場所名を出したいです。

現在の1件は次の構成です。

```
.list-item
  .list-item__marker      印
  .list-item__content
    .list-item__name      名称（多くは「名前の情報はありません」）
    .list-item__meta      「地図の中心から 約240 m ・ 東京都」
    .list-item__tags      特徴の札
```

**多くのトイレは名前が無いので、いま一覧は「名前の情報はありません」だらけです。**
場所名が分かるものは、そちらを主役にしたいです。

- 場所名を出す要素 `.list-item__place` を追加してください
- 名前が無く場所が分かる場合は、**場所名が主役**（大きい文字）になり、
  「名前の情報はありません」を繰り返さない見せ方にしてください
  （Claude Code 側で、名前が無いときは `.list-item__name` に場所名を入れ、
   `.list-item__place` に「駅・駅ビルの中」などの種類を入れる、といった使い分けができます。
   どちらの要素に何を入れるとよいか、**あなたが決めて指定してください**）
- `derived` のものは一覧でも区別が付くようにしてください（札 `.tag--derived` など）

### 6. 場所の種類を示す札

`.tag` に、場所の種類用のバリエーションを足してください。

- `.tag--place-station` `.tag--place-shop` `.tag--place-park`
  `.tag--place-roadside` `.tag--place-public`
- 文字は「駅の中」「商業施設の中」「公園の中」「道の駅・SA/PA」「公共施設の中」
- 既存の設備の札（`.tag--multi` など）と**見分けが付く**ようにしてください
  （設備の札と場所の札は意味が違うため）

## 制約（これまでと同じ）

- 素のCSSのみ。既存のデザイントークンを使うこと。
- 幅320pxのスマホ〜PCまで破綻しないこと。文字サイズ「大」でも破綻しないこと。
- ライト／ダーク両対応。`prefers-reduced-motion` 対応。
- タップ領域48px以上。色だけに頼らないこと。
- すべて日本語。高齢者にも通じる平易な言葉で。
