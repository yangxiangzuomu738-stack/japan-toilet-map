# デザイン依頼書 その6：「近くのトイレ一覧」パネル

## なぜ必要か

現在、トイレを選ぶには **地図上のマーカーをクリック／タップする** しかありません。
これには次の問題があります。

1. **キーボードだけで操作する人・スクリーンリーダーを使う人が、トイレを1件も選べない。**
   地図は `<canvas>` なので、マーカーはキーボードのフォーカスが当たりません。
2. 手が震える方や、細かいタップが苦手な高齢者にとって、
   小さなマーカーを正確に押すのは負担が大きい。
3. 「近くにどれだけあるか」「どれがいちばん近いか」が地図だけでは分かりにくい。

Googleマップにも iPhone のマップにも「一覧」があります。
このアプリにも、**地図に表示中のトイレを上から順に並べた一覧** を用意します。

## 対象ファイル

- `web/design/ui-list.html`（新規作成）
- `web/styles.css`（追記）
- `web/design/icons.js`（必要ならアイコン追加）
- `web/design/DESIGN_SPEC.md`（追記）

`web/index.html` と `web/js/*.js` は Claude Code 担当です。読むだけで編集しないでください。

## 作ってほしいもの

### 1. 一覧を開くボタン

`#map-controls` の中に追加する前提で、HTML断片とCSSを用意してください。

- `id="open-list"`、`aria-label="この範囲のトイレ一覧"`、`aria-controls="list-panel"`
- 既存の `.map-control` / `.map-control__button` と同じ見た目
- アイコンは `icons.js` に **`list`** を追加してください

### 2. 一覧パネル

既存の `.side-panel` と同じ体裁（スマホでは下からのシート、PCでは左パネル）で、
`<aside class="side-panel side-panel--list" id="list-panel" ... hidden>` を作ってください。

構成:

- ヘッダー: タイトル「この範囲のトイレ」＋閉じるボタン `id="close-list"`
- 件数表示 `id="list-count"`（例「表示中 42 件」）
  - 件数が多いときは「近い順に 50 件まで表示しています」と補足できるよう、
    補足用の要素 `id="list-note"` も用意してください
- 並び順の切り替え `id="list-sort"`（`<select>` か、押しやすいボタン2つ）
  - 「地図の中心から近い順」と「名前がある順」の2つ
- 一覧本体 `<ul id="list-items" class="list-items">`（JavaScript が中身を作ります）
- 空のときの表示 `id="list-empty"`（「この範囲にトイレがありません」）

### 3. 一覧の1件分（テンプレート）

`<template id="list-item-template">` の中に、**1件分のひな形** を作ってください。
JavaScript が複製して値を入れます。

必要な要素とクラス:

| 要素 | クラス | 入る内容 |
|---|---|---|
| 全体（押せるボタン） | `.list-item` | クリックで地図がそこへ移動し、詳細が開く |
| マーカーの印 | `.list-item__marker` | 車いす対応あり／なし／不明のSVG（凡例と同じ絵） |
| 名称 | `.list-item__name` | 例「日比谷公園 公衆トイレ」／無い場合「名前の情報はありません」 |
| 距離・場所 | `.list-item__meta` | 例「地図の中心から 約240 m ・ 東京都」 |
| 特徴の札 | `.list-item__tags` | 中に `.tag` を0〜3個入れる（例「車いす対応」「洋式」「24時間」） |

**重要**: 1件の高さは最低 **64px**、押せる範囲は横幅いっぱいにしてください。
高齢者・視力の弱い方が迷わず押せることを最優先にしてください。

`.tag` は、意味ごとに見分けられるようにしてください（`.tag--multi` `.tag--style` `.tag--hours` など）。
色だけに頼らず、必ず文字で意味が分かるようにしてください。

### 4. キーボード操作

一覧はキーボードだけで完結できる必要があります。

- `.list-item` は `<button type="button">` にしてください
- フォーカスリングが背景に埋もれないよう、`:focus-visible` を明確に
- 一覧の中を上下矢印で移動する想定なので、フォーカス中の項目 `.list-item:focus-visible` が
  はっきり分かるようにしてください
- 現在選択中の項目には `aria-current="true"` が付きます。その状態のスタイルも用意してください

### 5. パネル同士の関係

現在、`#filter-panel` / `#detail-panel` / `#info-panel` があり、
これに `#list-panel` が加わります。
**PCでは一覧と詳細が同時に開くこと**が想定されます（一覧で選ぶ→詳細が出る）。
2つ並んでも破綻しないレイアウトにしてください。
スマホでは、同時に開かず切り替わる前提で構いません。

## 制約（これまでと同じ）

- 素のCSSのみ。既存のデザイントークンを使うこと。
- 幅320pxのスマホ〜PCまで破綻しないこと。
- 文字サイズ「大」でも破綻しないこと。
- ライト／ダーク両対応。
- `prefers-reduced-motion` 対応。
